# StratumRO Evidence-First Scientific Verification Rules

## 1. Scientific Claim Classification
Every technical claim, benchmark score, or geodetic metric produced by an agent must be explicitly categorized into one of the 8 canonical states:

1. **IMPLEMENTED:** Code exists on disk and is importable.
2. **TESTED:** Automated unit or regression tests executed cleanly with reported exit code.
3. **REPRODUCED:** Independently re-executed on a clean environment, reproducing identical numbers.
4. **MEASURED:** An empirical numerical value exists from a specific script execution.
5. **VALIDATED:** Compared against an appropriate independent reference dataset.
6. **FIELD-VALIDATED:** Verified against ground-truth terrestrial survey coordinates (GNSS RTK, Total Station). *Never claim field validation without physical terrestrial survey logs!*
7. **THEORETICAL:** Expected mathematically, but not yet empirically proven in the field.
8. **UNVERIFIED:** Claim exists in text or previous audits, but cannot be reproduced from current code/data.

## 2. Testing Standard
- When modifying code or pipeline configurations, always run:
  ```powershell
  venv\Scripts\python -m unittest discover stratum_ro/test
  ```
- Report exact counts (e.g. `184 passed, 9 skipped, 0 failed` out of 193 discovered).
- **A skipped test is NOT a passed test.**
- **A passing unit test is NOT proof of real-world cadastral accuracy.** Real field accuracy requires evaluation against reference cadastral footprints (`data/ground_truth/tier1_teren.geojson`).

## 3. Transparency on Recall & Denominators
- Never conceal false positives or low recall.
- Always explicitly report all 3 fundamental denominators:
  1. True Positives (TP)
  2. Matched References (Ground Truth count)
  3. Total Predictions generated by the pipeline.
